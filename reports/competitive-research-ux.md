# PDF Context Translator 竞品体验研究（V2）

## 研究范围与样本
本轮对 8 类阅读/批注产品做了在线资料研究与体验模式拆解（重点看：阅读流畅度、注释/翻译路径、状态管理、跨设备一致性）。

1. Kindle Web / Kindle Cloud Reader（亚马逊）
2. Instapaper（稍后读极简阅读范式）
3. Hypothes.is（协作批注）
4. Readwise Reader（重度阅读工作流）
5. Zotero PDF Reader（学术型注释+回链）
6. LiquidText（跨页/跨文档连接）
7. MarginNote（卡片化与知识重组）
8. Foxit / Acrobat 类传统 PDF 编辑器（企业文档工作流）

> 数据来源：公开产品页/帮助文档（见文末链接），用于抽象 UX 模式而非功能逐项对标。

## 关键 UX 模式（跨产品共性）

### 1) “阅读主任务优先”的画布策略
- **共同点**：正文是第一视觉焦点，工具条次级，详情区按需展开。
- **价值**：降低“工具噪音”，提升连续阅读时长。
- **代价**：高级操作入口更深，需要渐进披露设计。

### 2) “轻注释 + 重管理”二层结构
- **共同点**：正文内只放轻量标记（高亮/小气泡），完整元数据放侧栏列表。
- **价值**：不打断阅读，同时保留批量管理能力。
- **代价**：需要双向同步（正文点击 <-> 侧栏定位）。

### 3) 注释对象必须可回到上下文（Context Recoverability）
- **共同点**：注释不是孤立卡片，必须能“一键回到原页原位置”。
- **价值**：防止“摘抄失语境”。
- **代价**：锚点模型和页码变更容错要做好。

### 4) 失败可见、可恢复（Error Recoverability）
- **共同点**：翻译/网络失败不能吞掉，需明确状态并提供重试。
- **价值**：提升可控感与信任。
- **代价**：状态机复杂度增加（loading/success/error）。

### 5) 跨设备一致性：桌面分栏，移动抽屉
- **共同点**：桌面常驻侧栏，移动端底部抽屉/全屏层。
- **价值**：兼顾信息密度与触控可达性。
- **代价**：响应式行为需要严格定义（不是单纯缩放）。

### 6) 持久化不只保存“结果”，还要保存“过程状态”
- **共同点**：保存模式、页码、注释集合；部分产品保存筛选/排序。
- **价值**：恢复成本低，用户感觉“会记得我”。
- **代价**：版本迁移与坏数据恢复策略必需。

## 对本项目最有价值的 10 条设计启发

1. **工具条吸顶 + 最少必要控件**：上传、模式切换、页码跳转、上下页。
2. **正文第一，注释第二**：注释详情移至侧栏，不在正文内堆叠过多信息。
3. **正文锚点保留轻标签**：点击词后仅显示小型气泡（词+译+短上下文）。
4. **全局注释面板卡片化**：页码、状态、操作（定位/重试/删除）。
5. **翻译状态机显式化**：loading -> done / error。
6. **错误要可操作**：错误文案+重试按钮，而非静默失败。
7. **页码跳转要容忍渐进渲染**：目标页未渲染时自动重试定位。
8. **移动端注释改抽屉面板**：避免占用主阅读区。
9. **读者位置记忆**：恢复最后阅读页与模式。
10. **注释可清空但仅限当前文档**：防误删其他文档记录。

## 竞品模式取舍总结（Trade-offs）

- **极简阅读（Instapaper）** vs **全能工作台（LiquidText/MarginNote）**  
  - 极简：学习成本低，但结构化知识管理弱。  
  - 全能：能力强，但认知负担高。

- **文内直接展示大量批注** vs **文内轻展示+侧栏重展示**  
  - 前者：上下文近，但遮挡阅读。  
  - 后者：阅读更顺，但需要良好“定位回跳”。

- **自动翻译即时出结果** vs **可追溯可重试的状态化翻译**  
  - 即时：看似快，但失败不可见。  
  - 状态化：更稳健，可维护性更高。
